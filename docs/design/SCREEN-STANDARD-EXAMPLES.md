## Deliberate deviations recorded in Wave 0

- **Payroll money actions are Tier 2, not Tier 3.** Standard section 5 puts "irreversible, money or legal" at Tier 3 (impact preview, typed confirmation, required reason, step-up MFA). Wave 0 migrated the five native dialogs in `PayrollPage.tsx` (delete a draft run, outside-the-bank-file confirmation, contra journal on reversal, payment-reversal reason, settlement cancel) to Tier 2 on purpose: each is reversible by a contra entry or is a draft, the reason is already a required field of the form (or asked for in the dialog), and the server enforces the real controls (permission `payroll.export` / `payroll.approve`, batch locks, step-up where `StepUpHost` applies). Finalising a run and purging tenant data stay Tier 3 when they are migrated. Revisit if Finance wants a typed confirmation on contra journals.
- **No client-side reason length cap.** The server sets no limit on leave reject/cancel/void notes, requisition rejection, or the payroll reversal, contra-journal and settlement-cancel reasons (no `MaxLength` or `StringLength`, free-text or unbounded columns), so the confirm dialog's reason box has no default cap; a caller passes `reason.maxLength` only when the server has one.
- **Attendance Live Dashboard records in an inline panel, not a drawer (Wave 1, decided by the owner/CTO).** Example B-1 puts the punch form in a drawer. The shipped record panel (#327) runs a chunked, multi-minute mass entry and then "Process now", and the daily records below it are what the user watches fill in. The panel is closed on load (never auto-opened); the header's one primary, "Record attendance", and the empty-state action open it, and while it is open that button becomes a secondary "Close" so the panel's own submit is the single primary. The panel has a ghost Close and Esc, focus returns to the header button, and a run that is still going while it is closed shows as a "Recording n of m" chip in the header that reopens it. Why inline and not a drawer: the panel is two panes (employee picker about 500 px, entry form about 500 px) and needs about 1000 px; a 480 px drawer would stack them and halve the list height, and a modal drawer makes the page inert and unmounts the run when closed. The panel is hidden, never unmounted, so a run or a half-typed entry survives closing it. Revisit only if a non-modal 640 px drawer primitive exists; inline will always push the table out of view while it is open. The table takes the full width; device health and exceptions sit under it and only form a rail from 1680 px (`min-[1680px]`, because the `rail` and `wide` breakpoints are not in `tailwind.config.ts` yet). Tabs stay at 7: the real-stack specs address "Reports" and "Insights" by name. The four KPI tiles are filter buttons (Present, Absent and Late set the status filter; Missing punch narrows the loaded rows client-side, because the API takes no such status) and the result count is announced in the live region. Under 640 px the table becomes a card list so Missing punch and late minutes are never hidden.
