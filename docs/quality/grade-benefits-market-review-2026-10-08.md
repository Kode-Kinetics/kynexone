# Grade benefits: market review and delivery criteria

Reviewed 8 October 2026 against official product documentation and the current KynexOne source. This is a workflow comparison, not a claim of complete feature parity or a review of vendor editions/licensing.

The requested operating model is consistent with enterprise HR systems: maintain the standard package centrally, evaluate it from the employee's assignment, apply new-hire defaults, and handle employee-specific exceptions separately. The key distinction is between eligibility, an actual enrollment, a fixed contractual entitlement, and a payroll deduction; those records have different consequences.

## Official market evidence

| Product | Documented behavior | Consequence for KynexOne |
| --- | --- | --- |
| SAP SuccessFactors Employee Central | SAP's published benefits test script describes automatic enrollment based on pay grade and routing those enrollments to the HR Business Partner for approval. Its implementation guide describes hire events that can create benefit enrollment, deduction, or exception records according to configured criteria. | Show the grade's defaults at hire, record how each assignment was created, and make approval policy explicit. Automatic deduction is a configurable vendor capability; KynexOne's grade entitlement must not silently create a loan payout or payroll charge. |
| Oracle Fusion Cloud HCM | Benefit eligibility profiles include grade, job, position, legal entity, hire date, and probation criteria. Default enrollment can give new participants the default while preserving current participants' enrollment; an automatic enrollment method can prevent employee changes to those defaults. | Keep a simple grade-first setup with company and effective-date scope. Preserve an employee's existing exception or waiver on retries and subsequent default evaluation. |
| Microsoft Dynamics 365 Human Resources | Rules can combine job, department, legal entity, employment conditions and validity dates. Its overview documents autoenrollment rules, optional employee selection, administrator confirmation, and processing for hires and life events. | Use one explainable evaluation for preview and save; show why a benefit applies, when it starts, and whether further confirmation is required. |

These sources support controlled overrides; they do not establish that every vendor enforces two-person approval for every benefit exception. ## KynexOne assessment

KynexOne currently has two benefit models, selected by the tenant's `release_a` feature. They must not both issue the same employee's benefits.

| Model | Behavior verified in source | Delivery boundary |
| --- | --- | --- |
| Legacy plans and enrollments | `BenefitsController` evaluates plan/company/date/grade rules. The new `GradeBenefitDefaults` service stages default enrollment snapshots in the employee creation transaction and skips tenants with `release_a`. | Verify direct hire, approved draft/recruitment hire, and import. Exceptions need server authorization, employee/company scope, reason, history and safe effective dates. |
| Canonical grade matrix and employee package (`release_a`) | `EntitlementResolver` derives a live grade standard for an employee without a verified frozen row. Contract activation calls `PackageFreezeOnActivation` to freeze eligible contractual defaults. Existing package confirmation requires a different HR user and signed-contract evidence. | The live grade standard is a preview until fixed. The existing package panel is not an arbitrary employee exception editor: its actions are freeze/propose/confirm/reject. The writer accepts a future approved renewal's exception payload, but the renewal offer service/controller are currently stubs. A package or renewal link alone must not be reported as delivery of later employee exceptions. |

Code evidence: `backend-dotnet/Zayra.Api/Infrastructure/Entitlements/EntitlementResolver.cs`, `PackageFreezeOnActivation.cs`, `EntitlementWriter.cs`; `backend-dotnet/Zayra.Api/Controllers/Entitlements/EmployeePackageController.cs`; `frontend/src/components/entitlements/EmployeePackagePanel.tsx`; `backend-dotnet/Zayra.Api/Infrastructure/Benefits/GradeBenefitDefaults.cs`.

**Separate canonical-module release blocker:** the existing contract-version API (`Controllers/Compliance/ContractsController.cs`, `Supersede`) cannot supply this missing exception editor: its request has no benefit values and activation carries the predecessor package. `frontend/src/api/compliance.ts` declares `supersede`, but there is no UI caller. `ContractRenewalsController.Offer.cs` and `RenewalOfferService.cs` are empty; `ContractRenewalApprovalSync.cs` throws `NotImplementedException`. Canonical employee exceptions therefore require an implemented, governed proposal/decision path, not a navigation change. This delivery targets the legacy Benefits Administration screen shown in the request; it does not close that separate canonical-module blocker.

## Acceptance criteria for this change

1. **Grade-led setup and hire preview.** HR can see each grade's benefit, coverage or limit, employing-company scope, and start/end dates before saving an employee. Missing configuration is distinguishable from a deliberately unavailable benefit.
2. **Atomic default assignment.** The employee and defaults commit together on every supported creation path. A rollback leaves neither; an identical replay creates no duplicate and does not restore a waived benefit. No automatic contribution, payroll deduction or loan disbursement follows from entitlement alone.
3. **Controlled employee exception.** Only authorized HR/relevant authority can act within their company scope. Changes carry a reason, effective dates, before/after values and actor identity. Self-approval must be prevented where the configured workflow requires a second decision-maker. Tenant, employee and company IDs must be revalidated server-side.
4. **Clear package state.** Show “Grade default”, “Exception”, “Awaiting eligibility”, and “Not yet fixed” accurately. Employee self-service shows only that employee's benefits. A read-only user sees the package without mutation controls and receives a denial on direct API mutation.
5. **Preserve signed and processed history.** Editing a grade table cannot silently rewrite a fixed contract package or deductions already processed. Corrections and renewals retain their existing governed paths.
6. **Verify with realistic data.** Cover two grades, two companies, another tenant, an inactive/expired plan, a future hire, a waiting period, a probation requirement, a waiver, an exception, import replay, and a forced transaction failure. Record rendered evidence with the actual signed-in persona and build provenance.

## Follow-up improvements to evaluate

- Delayed eligibility needs explicit processing. The new default service now stages future assignments when the service/probation eligibility date is known. When probation completion is unknown, a later review/event still needs to re-evaluate the benefit. Show the future start date and distinguish scheduled coverage from coverage in effect.
- Promote grade/company changes into an effective-dated review event. Dynamics explicitly notes that later ineligibility does not automatically unenroll an existing participant; KynexOne should show the proposed change and preserve approved exceptions. [Dynamics rules and life events](https://learn.microsoft.com/en-us/dynamics365/human-resources/hr-benefits-setup-eligibility-rules).
- The new default service batch-loads plans and rules and queries existing enrollments for the import batch. Verify the existing 250-row import use case to protect that behavior.
- Provide exception expiry, renewal review and exception reporting. These controls make exceptional packages discoverable after the original administrator has moved on.

These are product recommendations inferred from the documented workflows and the source review. Live service behavior and end-to-end acceptance must be verified separately; this review does not certify deployment.
