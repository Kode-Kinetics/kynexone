## Rules used (hand accounting)
1. Resolution order: employee override, position, department, parent department, company default (spec 2.2). Invalid CC at a level is a hard error, never falls through.
2. Round once per employee x component row to 2 dp half-up (away from zero; GOSI statutory components half-even, see F-ROUND), then group by (component, CC). A CC line is an exact sum, so ordinary earnings need no residue and there is NO 5199 rounding line in any scenario of this pack (drift 0.00).
3. Only Expense accounts carry a CC. Liability/asset lines (2100, 2101, 2106, 2107, 2300, 2320, 1000, 1410) are uncosted. Contra-expense credit 5113 IS costed. Employer GOSI: DR 5101 per CC (employee's CC), CR 2106 once, uncosted.
4. Net payable = all earnings - employee deductions (GOSI-ANN-EE, GOSI-SANED-EE, loan, advance, settlement recovery). Employer GOSI is outside net.
5. Largest remainder (spec 2.6): floor(total x w / W) in minor units, spare units to largest fractional remainder, ties by ordinal CC code.
6. GOSI, taken from the app's KSA country pack (exact rule keys and values in `inputs/08_gosi_rates.csv`): covered wage = basic + housing, capped at `gosi.covered_wage_ceiling_sar` 45,000 (monthly). One payslip line per component, each rounded separately per employee: Saudi `GOSI-ANN-EE`, `GOSI-SANED-EE` (employee, credit 2101 each), `GOSI-ANN-ER`, `GOSI-SANED-ER` (employer, credit 2106 each); `GOSI-OH-ER` (employer, everyone, credit 2106). Employer lines pair to DR 5101 per cost centre. Annuities depend on the Saudi's cohort: existing subscriber or unknown cohort = `gosi.saudi_employee_rate`/`gosi.saudi_employer_rate` 9%/9%; new entrant (first GOSI registration on or after 2024-07-03) = `gosi.new_entrant_*_rate`, 10% each side for 2026-09 and 2026-10 (step effective 2026-07-01). SANED `gosi.saned_rate` 0.75% each side (Saudis only). OH `gosi.expat_occupational_hazard_rate` 2% employer. Cohorts in the fixture: E001, E002, E005 PreJuly2024; E006 Unknown (9%, pack reports "unverified"); E008 NewEntrant (10%, first registered 2025-02-10). Non-Saudis: OH only.
7. Void: contra mirrors every original line (same account, CC, amount, flipped side), posted in the NEXT open period (2026-10) because 2026-09 is closed.
8. Class re-route (M2): company-scope mapping (EARN:BASIC, COGS) to 5011 and (EARN:HOUSING, COGS) to 5012. Only lines whose CC has class COGS (CC-300) move. M1 journal is untouched.

## Flags: where the app pack may disagree with current GOSI law (NOT changed in the oracle)
- F-LAW-1: the new-entrant schedule (9% Jul 2024, +0.5 pt each July to 11% in 2028) is sourced in the pack from secondary sources (Oracle HCM, Argaam). Confirm the 10% step for 2026-07 against the GOSI circular.
- F-LAW-2: an Unknown cohort is priced at the existing 9% with a warning; if E006 was in fact first registered after 2024-07-03 the correct rate is 10%.
- F-LAW-3: no contributory-wage floor is applied (1,500 / 400 minimums only raise a validator warning); GOSI minimums are therefore unmodelled.
- F-LAW-4: GCC nationals and bonus/arrears inclusion in the covered wage follow pack rules not exercised here.
- F-ROUND (corrected, AM-33): the payroll engine rounds each statutory component with C# `Math.Round(x, 2)` (half to even). The fixture DOES contain exact ties: SANED 0.75% on a covered wage of 18,750.00 (E001) is 140.625 and on 8,750.00 (E005) is 65.625. The first version of this oracle rounded them half-up (140.63, 65.63); the engine's half-even value (140.62, 65.62) is authoritative for v1, because a costing release must not move pay amounts, and the GOSI register, journals, totals and trial balances here are regenerated from it (EE and ER rows, M1 and M2). Whether GOSI's own rounding rule is half-up is a separate statutory item for the KSA pack, not for this release. The spec's cost-centre allocator uses AwayFromZero (that is a different operation and is unchanged).

## Rounding and allocation arithmetic
Full tables in `expected/allocation_cases.csv` and `allocation_vectors.csv`.
- Bonus accrual 2,899.99 = 289,999 minor over weights 100,000 x 3 (W = 300,000). Each floor = 96,666, fraction 1/3 each; floors sum 289,998; 1 spare unit; three-way tie so ties go to code order: CC-110 gets it. Result 966.67 / 966.66 / 966.66.
- Bonus remainder 100.01 = 10,001 minor. Floor 3,333 each, fraction 2/3 each; floors sum 9,999; 2 spare units; tie on fraction so CC-110 and CC-200 win: 33.34 / 33.34 / 33.33 (same as T-013).
- Per-CC bonus expense across both journals: CC-110 1,000.01, CC-200 1,000.00, CC-300 999.99 (sum 3,000.00). The employee-level register shows 1,000 each, so the tie-out file carries +0.01 / 0.00 / -0.01 explained differences. Any other difference is a defect.
- AV5: 666.67 over 1:3 = 16,666.75 and 50,000.25: floors 16,666 / 50,000, 1 spare unit to the .75 part (CC-200 first), so 166.67 / 500.00.
- AV8 shows ordinal (not numeric) tie-break: CC-1000 < CC-110 < CC-200. AV7 negative total re-signs after allocating |x|. AV6 zero weights returns one uncosted part. AV2 is KWD scale 3 (100.001 to 33.334 / 33.334 / 33.333).
- Other rounding cases: E009 transport 500 x 20/30 = 333.333 to 333.33; E008 GOSI components above; E009 expat OH 2% x (4,000 + 1,000) = 100.00.
